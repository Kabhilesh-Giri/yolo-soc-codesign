
1. Create Hardware Module - Receiver

Objective: demonstrate that CPU software can start the Receiver and retrieve the replayed samples through the modeled hardware interface.

-> Read the signal data from the csv with 1 us delay
-> Bind the Receiver's register interface just like the vector_processor's control status register.
-> the CSR will contain the data as either 0x01 or 0x02 means
0x00 = print the read signal values
0x01 = APU Path
0x02 = ADC Path

-> CSR Register has only two modes 0 or 1 exactly replicating the vector processor.
-> QEMU Sw/receiver_testbench.cc should keep polling until the CSR bit changed to 0. (exactly like vector processor)

-> the receiver should have 2 us delay to send the data out (Increase that in SystemC simulation time)

-> this hardware should have control status register such that when the firmware from the CPU triggers this CSR of receiver the device should reading the csv file with one us delay (Increase that in SystemC simulation time)

Make sure to bind this hardware with the Zyncdemo.cc and provide the address as (0x50000000)

APU and ADC are different Hardware modules that will developed in the later issues
For this CSR Instruction Bit 0x01 = APU Path or 0x02 = ADC Path the Receiver should contact that particular device via the TLM through the Interconnect.
